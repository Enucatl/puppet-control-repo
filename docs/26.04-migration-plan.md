# Ubuntu 26.04 Migration Plan

## Current State

The Ubuntu server template is currently pinned to Ubuntu 24.04 Noble in
`proxmox/ubuntu-server-template.sh`:

- VM name: `ubuntu-server-2404-template`
- Image: `noble-server-cloudimg-amd64.img`
- Image URL: `https://cloud-images.ubuntu.com/noble/current/noble-server-cloudimg-amd64.img`

The Docker VM provisioning flow clones template ID `9000`, then applies a
Docker-specific cloud-init snippet and runs Puppet. The existing Ubuntu hosts
to migrate are:

- `complex.home.arpa` on `proxmox-cortex.home.arpa`
- `forbearance.home.arpa` on `proxmox.home.arpa`
- `docker.home.arpa` on `proxmox.home.arpa`

`complex` is the best pilot candidate because it has a smaller workload set:
Wolf, vLLM, NVIDIA Docker support, and an NFS export.

## Verified 26.04 Package Findings

Ubuntu 26.04 LTS uses the apt codename `resolute`. The release nickname is
Resolute Raccoon, but package repositories use `resolute`.

The 26.04 cloud image exists:

```text
https://cloud-images.ubuntu.com/resolute/current/resolute-server-cloudimg-amd64.img
```

Docker has a `resolute` repository:

```text
https://download.docker.com/linux/ubuntu/dists/resolute/Release
```

The graphics-drivers PPA has a `resolute` repository, but currently exposes
only `nvidia-driver-580-open` for the open driver package family:

```text
nvidia-driver-580-open 580.126.09-0ubuntu1
```

Direct searches of the live PPA index did not find `nvidia-driver-590-open` or
`nvidia-driver-590`. The current `complex` Hiera data pins
`nvidia-driver-590-open`, so the 26.04 pilot should use `nvidia-driver-580-open`
unless `590` becomes available before implementation.

Puppet Labs has not yet published a 26.04 release package at the checked
locations:

```text
https://apt.puppet.com/puppet8-release-resolute.deb
https://apt-puppetcore.puppet.com/public/puppet8-release-resolute.deb
```

Both returned 404 at the time of investigation.

Ubuntu 26.04 Universe does package Puppet independently from Puppet Labs:

```text
puppet-agent  8.10.0-6
puppetserver  8.7.0-6ubuntu1
puppetdb      8.8.1-1~exp1
r10k          5.0.0-2ubuntu2
```

This is not equivalent to the current installation. The current host reports:

```text
/opt/puppetlabs/bin/puppet agent --version
8.18.0
```

The Ubuntu package provides `/usr/bin/puppet`, while this repo's provisioning
paths assume `/opt/puppetlabs/bin/puppet`.

## Recommended Strategy

Use a parallel rebuild strategy, not an in-place release upgrade.

Create a separate 26.04 template, leaving the current 24.04 template ID `9000`
available for rollback. Use a new template ID such as `9026` for the 26.04
pilot.

For `complex`, create a temporary pilot VM such as `complex26.home.arpa` from
the 26.04 template. Copy the existing `complex` Hiera data for the pilot and
adjust only the parts required for 26.04 validation.

Treat `complex` as mostly recreatable from Puppet and git repositories. Do not
bulk-copy Docker runtime state by default. Migrate only known local state, such
as `/opt/wolf` configuration and any explicitly identified Wolf secrets or
configuration files found during the pre-cutover inventory.

## Pilot Flow

1. Add a 26.04 template build path using the `resolute` cloud image and a new
   template ID.
2. Decide how the pilot installs Puppet:
   - Preferred production path: wait for Puppet Labs to publish official
     `resolute` packages and keep `/opt/puppetlabs/bin/puppet`.
   - Acceptable pilot workaround: install Ubuntu's `puppet-agent` package and
     use `/usr/bin/puppet` only for the disposable pilot.
3. Deploy `complex26.home.arpa` from the 26.04 template.
4. Apply Puppet until the catalog converges cleanly.
5. Validate Docker, NVIDIA, the NVIDIA container runtime, Wolf, vLLM, and the
   NFS export.
6. Copy the required `/opt/wolf` state and re-test Wolf/Moonlight behavior.
7. If the pilot succeeds, schedule a final cutover for `complex.home.arpa`.

## Production Gates

Do not migrate `docker.home.arpa`, which hosts the Puppet server stack, until
the Puppet packaging decision is resolved.

The preferred production gate is official Puppet Labs support for Ubuntu 26.04.
Moving the Puppet server from Puppet Labs packages to Ubuntu-maintained packages
would change version, packaging layout, service behavior, and operational
support model at the same time as the OS migration.

Do not point Ubuntu 26.04 hosts at the Noble Puppet Labs repository except as a
short-lived experiment. It is unsupported and undermines the goal of proving a
clean 26.04 baseline.

Do not migrate `docker.home.arpa` before `complex` and `forbearance`. It has the
largest blast radius: many compose projects, Vault and Traefik certificate
state, ACLs, cron backups, Samba-related state, and the Puppet control repo
deployment itself.

## Rollout Order

1. `complex.home.arpa`
2. `forbearance.home.arpa`
3. `docker.home.arpa`

Keep each old VM stopped but not destroyed until the replacement has completed
validation and run successfully through an appropriate maintenance window.

## Validation Checklist

- `lsb_release -a` reports Ubuntu 26.04.
- Cloud-init completes successfully.
- QEMU guest agent is running.
- SSH access works.
- Puppet agent converges cleanly.
- Docker service starts and `docker compose` works.
- NVIDIA driver loads and `nvidia-smi` works.
- NVIDIA container runtime works.
- Wolf and vLLM deploy successfully.
- `/opt/wolf` configuration is present and functional.
- NFS exports and mounts behave as expected.
- The old VM can still be restarted for rollback.
